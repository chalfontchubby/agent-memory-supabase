Supabase-hosted shared agent memory. The MCP server runs as a Supabase Edge Function over HTTP with its own hashed long-lived bearer tokens. Everything lives in an agent_memory schema. Memories belong to scopes such as predbat-devs, with per-member read or write grants enforced by row-level security keyed on the member id, not auth.uid, because bots are members too and need no auth.users row. The admin, import and backup scripts run with the service-role key from an environment variable that is never committed. Delete and prune are soft, setting deleted_at, and a memory_history table records every change with the member who made it so that a bad bot run can be traced and reversed. Embeddings use the built-in gte-small model with 384 dimensions, one embedding per Edge Function call wherever possible, because the free tier limits CPU time per request. Search is hybrid: Postgres full-text rank plus pgvector cosine similarity fused with reciprocal rank fusion with k of sixty, then temporal decay with a thirty day half-life, an importance multiplier from access frequency and recency, and an evergreen exemption for memories tagged never-forget. The import script reads an existing LanceDB folder or its hardcopy JSON, dry run by default, and selects memories by include and exclude tag filters plus an explicit list of identifiers because a tag filter alone may let private memories through.
