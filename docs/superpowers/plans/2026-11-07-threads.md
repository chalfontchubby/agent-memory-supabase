# Discussion Threads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scoped, append-only discussion threads linked to memories. Agent-held sessions subscribe to threads and
poll `whats_new`, and memory and thread writes record the session.

**Architecture:** One new migration holds the tables, the RLS select policies and every write as a SECURITY DEFINER
function, so the rules live in Postgres as they do today. A new `PgThreadStore` (`_shared/thread-store.ts`) runs
through `withMember` and calls those functions. Reads go through RLS-protected views. A new
`_shared/thread-tools.ts` registers 11 tools for every member, plus `admin_delete_thread` for admins. `recall`
attaches linked threads, and memory writes accept a session.

**Tech Stack:** as the existing project: Postgres 17 migrations + pgTAP, Deno, `npm:postgres@3.4.5`,
`npm:@modelcontextprotocol/server@2.4.0`, `npm:zod@4.6.7`.

**Spec:** [docs/superpowers/specs/2026-11-07-threads-design.md](../specs/2026-11-07-threads-design.md). Read §3 and §4
before any task: the session and marker rules there are binding.

## Global Constraints

- **All schema work goes in ONE NEW migration, `supabase/migrations/20261107180000_threads.sql`.** Tasks 1–3 append to
  it. No earlier migration changes, and `supabase db reset` must build from empty. Replacing an existing function or
  view uses `create or replace` (or `alter policy`) inside the new file.
- **Every function** is `security definer`, `set search_path = ''`, with fully qualified names, then
  `revoke execute … from public`. Member-callable functions are then granted to `agent_memory_member`. `adm_*`, purge,
  erase and restore stay postgres-only.
- **Members get `select` only on the new tables and views.** They get no insert, update or delete grants. Every write
  goes through a function.
- **User-safe errors are `raise exception '<text>'`** (SQLSTATE P0001). The TS layer turns P0001 into `StoreError(message)`,
  exactly as `PgAdminStore.run` does, and anything else into `Database error`.
- **Exact error texts:**
  - `Thread <id> not found`
  - `Memory <id> not found`
  - `Session not found`
  - `Scope '<name>' not found`
  - `No write access to scope '<name>'`
  - `Title must be 1-200 characters`
  - `Post body is empty`
  - `content too long (max 20000 characters)`
  - `Thread is already resolved`
  - `Thread is already open`
  - `Session label '<label>' is already in use`
  - `Session label does not match`
  - `Session label must be 1-64 characters with no leading or trailing space`
  - `At most 20 memory_ids`
  - `Pass session or session_label`
- **"Not found" texts read the same whether the thing is absent, unreadable or another member's.**
- **IDs are checked in TS before they reach SQL.** Any `thread_id`, `memory_id` or `session` that isn't a UUID gets
  the matching "not found" text and no query runs.
- **Timestamps that must round-trip** (backup and restore) bind as text: `${x}::text::timestamptz`.
- **Tool results** use the existing `success()` shape. Thread tool failures use `failure()`, which returns the message
  alone.
- **Limits** go in `_shared/limits.ts`: `THREAD_TITLE_MAX = 200`, `THREAD_READ_DEFAULT = 20`, `THREAD_LINKS_MAX = 20`,
  `SESSION_LABEL_MAX = 64`. Post bodies use `MAX_CONTENT_CHARS`, and read limits use `checkLimit` (1–100).
- **The repo is public.** No project ref and no personal names in committed files.

## Review Focus

1. **A mistyped label in `whats_new`, `read_thread`, `store` or `update`** must give `Session not found` and create no
   session row. Test: Task 2, `non-creating callers never create a session`.
2. **A grant revoked after subscribing.** The thread drops out of `whats_new`, `read_thread` says
   `Thread <id> not found`, and `post` is refused. Test: Task 2, `revoked grant hides subscribed thread`.
3. **Concurrent posts to one thread** get distinct, consecutive `seq` values with no gaps. Test: Task 4,
   `concurrent posts get consecutive seq`.
4. **A linked memory that is soft-deleted, then restored.** The link is hidden in `read_thread` and `recall`, then
   visible again. Test: Task 2, `soft-deleted memory hides its link until restored`.
5. **A title or body that is only whitespace** is refused with the exact texts above. A whitespace-only resolve note
   is stored as an empty body. Test: Task 2, `whitespace-only title and body are refused`.


Functions, member-executable:

- `owns_session(p uuid) returns boolean`
- `session_label(p uuid) returns text` (stable)
- `can_read_thread(p uuid) returns boolean`, true when the thread is live and its scope is readable
- `can_write_thread(p uuid) returns boolean`
- `resolve_session(p_id uuid, p_label text, p_create boolean) returns table (id uuid, label text, created boolean)`.
  It follows spec §4 precedence exactly:
  - id and label both null: create an unlabelled session if `p_create`, otherwise return zero rows.
  - Label only: find the caller's session with that label. If there isn't one, create it when `p_create`, otherwise
    raise `Session not found`.
  - Id only: the session must be the caller's, or raise `Session not found`.
  - Both: a session with no label gets the label attached. A different label raises `Session label does not match`.
  - A label that's already in use raises `Session label '<label>' is already in use`.
  - A label is trimmed and checked against `^\S(.*\S)?$`, 1–64 characters.
  - Bumps `last_seen_at` when it's more than 1 minute old.

Views, `security_invoker = true`, granted select:

- `thread_view`: `id, scope_id, scope, title, status, created_by (name), created_at, last_post_at, post_count,
  last_author (name of the author of the highest-seq post, or null), resolved_at, resolved_by (name)`.
- `thread_post_view`: `thread_id, seq, kind, body, author (name), session_id, session_label, created_at`.
- `memory_view` is replaced with two columns appended at the end: `created_session_label` and
  `updated_session_label`.

RLS policies (select only):

- `threads`: `can_read(scope_id) and deleted_at is null`.
- `thread_posts`: `can_read_thread(thread_id)`.
- `thread_links`: `can_read_thread(thread_id)` and the memory is visible through `memories` RLS.
- `agent_sessions`: `member_id = current_member_id()`.
- `thread_subscriptions`: `owns_session(session_id)`.

Memories:

- `alter policy` on `memories_insert` and `memories_update` adds
  `(created_session is null or owns_session(created_session))` and the same check on `updated_session`.
- Column grants: insert gets `created_session, updated_session`, and update gets `updated_session`.
- `memories_history_fn` is replaced, starting from the erase-migration version. It writes `session_id`:
  - `insert`: `new.created_session`
  - `update` and `move`: `new.updated_session`
  - `delete`, `restore` and `purge`: null

### Task 2: Thread write and poll functions

**Files:**
- Modify: `supabase/migrations/20261107180000_threads.sql` (append)
- Test: `supabase/tests/database/09_threads_functions.test.sql`

**Interfaces — Consumes:** Task 1's tables, `owns_session`, `can_read_thread` and `can_write_thread`.

**Produces:** these functions, member-executable. Each `p_session` argument must pass `owns_session`, or the
function raises `Session not found`. Each thread argument must pass `can_read_thread`, or the function raises
`Thread <id> not found`. Writes also need `can_write_thread`, or they raise `No write access to scope '<name>'`.

- `create_thread(p_scope_id uuid, p_title text, p_body text, p_memory_ids uuid[], p_session uuid) returns uuid`
  - Checks `can_write`.
  - Trims the title and checks it is 1–200 characters.
  - If the trimmed body is non-empty, writes it as post seq 1. A null or blank body means no posts.
  - Links each memory, raising `Memory <id> not found` unless it's readable and live.
  - Subscribes `p_session` when it's non-null, with the marker at `post_count`.
- `append_post(p_thread uuid, p_kind text, p_body text, p_session uuid) returns int`. This is private and NOT
  member-executable.
  - Takes `select … for update` on the thread.
  - `seq = post_count + 1`.
  - Updates `post_count` and `last_post_at`.
  - Inserts the post with `author_id = current_member_id()`.
  - Subscribes the session `on conflict do nothing`, with the marker at the new seq, and never moves an existing
    marker.
  - Returns the seq.
- `post_to_thread(p_thread uuid, p_body text, p_session uuid) returns int`. A body that's blank after trimming raises
  `Post body is empty`. Over 20000 characters raises the content-too-long text.
- `set_thread_status(p_thread uuid, p_status text, p_note text, p_session uuid) returns int`.
  - `'resolved'` on a resolved thread raises `Thread is already resolved`, and `'open'` on an open thread raises
    `Thread is already open`.
  - It appends a `resolve` or `reopen` post whose body is the trimmed note, or `''`.
  - It sets `status`, plus `resolved_at` and `resolved_by` (cleared on reopen).
- `link_memory(p_thread uuid, p_memory uuid) returns void`. Needs write on the thread, and the memory must be readable
  and live. Linking twice does nothing.
- `unlink_memory(p_thread uuid, p_memory uuid) returns boolean`.
- `subscribe(p_thread uuid, p_session uuid) returns void`. Needs read. Uses `on conflict do nothing`, with the marker
  at the current `post_count`.
- `unsubscribe(p_thread uuid, p_session uuid) returns boolean`.
- `mark_seen(p_session uuid, p_thread uuid, p_seq int) returns void`. Sets
  `last_seen_seq = greatest(last_seen_seq, p_seq)` and does nothing without a subscription.
- `whats_new(p_session uuid) returns table (thread_id uuid, title text, scope text, status text, new_posts int,
  last_post_at timestamptz, last_author text)`.
  - Lists the session's subscriptions where `can_read_thread` holds and
    `count(posts where seq > last_seen_seq and session_id is distinct from p_session) > 0`.
  - Ordered by `last_post_at desc`.
  - Bumps `last_seen_at`.

### Task 4: `PgThreadStore`

**Files:**

- Modify: `supabase/functions/_shared/types.ts` (thread types), `supabase/functions/_shared/limits.ts` (constants)

**Interfaces — Consumes:** the SQL functions and views from Tasks 1–3, and `withMember`.

**Produces:**

These types go in `types.ts`:

```ts
export interface SessionRef { session?: string; sessionLabel?: string }
export interface SessionInfo { id: string; label: string | null; created: boolean }
export type ThreadStatus = 'open' | 'resolved';
export interface ThreadSummary {
  id: string; scope: string; title: string; status: ThreadStatus; createdBy: string; createdAt: string;
  lastPostAt: string; postCount: number; lastAuthor: string | null;
}
export interface ThreadPost {
  seq: number; kind: 'post' | 'resolve' | 'reopen'; body: string; author: string;
  sessionLabel: string | null; createdAt: string; new?: boolean;
}
export interface ThreadLink { memoryId: string; scope: string; preview: string } // preview: first 200 chars
export interface ThreadView {
  thread: ThreadSummary; links: ThreadLink[]; posts: ThreadPost[]; hasOlder: boolean;
  moreUnread?: boolean; session?: SessionInfo;
}
export interface WhatsNewItem {
  threadId: string; title: string; scope: string; status: ThreadStatus; newPosts: number;
  lastPostAt: string; lastAuthor: string | null;
}
export interface LinkedThread { id: string; title: string; scope: string; status: ThreadStatus; lastPostAt: string }
```

These are the methods of `class PgThreadStore`, whose constructor is `(sql: Sql, memberId: string)`:

```ts
createThread(scope: string, title: string, body: string | undefined, memoryIds: string[], s: SessionRef)
  : Promise<{ thread: ThreadSummary; session: SessionInfo }>
post(threadId: string, body: string, s: SessionRef): Promise<{ post: ThreadPost; session: SessionInfo }>
setStatus(threadId: string, status: ThreadStatus, note: string | undefined, s: SessionRef)
  : Promise<{ thread: ThreadSummary; session: SessionInfo }>
readThread(threadId: string, o: { limit?: number; before?: number; after?: number }, s: SessionRef): Promise<ThreadView>
listThreads(o: { scopes?: string[]; status?: ThreadStatus | 'all'; limit?: number; before?: string })
  : Promise<{ threads: ThreadSummary[]; next: string | null }>
link(threadId: string, memoryId: string): Promise<void>
unlink(threadId: string, memoryId: string): Promise<boolean>
subscribe(threadId: string, s: SessionRef): Promise<{ session: SessionInfo }>
unsubscribe(threadId: string, s: SessionRef): Promise<boolean>
whatsNew(s: SessionRef): Promise<{ session: SessionInfo; threads: WhatsNewItem[] }>
linkedThreads(memoryIds: string[]): Promise<Record<string, LinkedThread[]>>
```

**Rules:**

- The thread-writing methods (`createThread`, `post`, `setStatus`, `subscribe`) call
  `resolve_session(…, p_create => true)` in the same transaction. `readThread`, `unsubscribe` and `whatsNew` use
  `false`.
- `whatsNew` and `unsubscribe` with an empty `SessionRef` throw `Pass session or session_label`.
- `createThread` resolves the scope through the same `scopeAccess` query that `PgMemoryStore` uses, which gives the
  scope texts. It rejects more than 20 `memoryIds`.
- `readThread`:
  - If `before` and `after` are both given, it throws `StoreError('Pass before or after, not both')`.
  - Catch-up applies when a session resolves, a subscription exists, and neither `before` nor `after` is given. It
    selects `seq > last_seen_seq` ascending, up to `limit + 1`, to work out `moreUnread`, then calls `mark_seen` with
    the last seq returned.
  - When there's nothing unread, or there's no session or subscription, it returns the latest `limit` posts in
    ascending order.
  - `new` is set only in catch-up mode: `true` for posts from other sessions.
  - `hasOlder` is true when the first post returned has `seq > 1`.
- `listThreads` defaults to `status: 'open'` and `limit: 20`, and orders by `(last_post_at desc, id desc)`. The cursor is
  `btoa(lastPostAt + '|' + id)`, and a malformed cursor throws `StoreError('Invalid cursor')`.
- `linkedThreads` makes one query over `thread_links` joined to `thread_view` for `memory_id = any($1)`.

### Task 5: Sessions on memory writes, labels on results, threads in recall

**Interfaces — Consumes:** `resolve_session`, the `memory_view` session columns, `PgThreadStore.linkedThreads` and

**Produces:**

- `Memory` gains optional `createdSession?: string`, `updatedSession?: string` (labels, omitted when null) and
  `threads?: LinkedThread[]`.
- `MemoryStore.store(scope, r, s?: SessionRef)`, `storeBatch(scope, rs, s?: SessionRef)` and
