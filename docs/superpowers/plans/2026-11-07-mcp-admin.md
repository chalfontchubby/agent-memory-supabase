# Admin through the MCP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin members manage scopes, members, grants and tokens through the MCP. Shell-only steps remain only for
admins themselves.

**Architecture:** The rules live once, in Postgres. One group of `postgres`-only functions (`adm_*`) does each admin
action and writes `admin_log`; the shell admin script calls these directly. A second group of member-executable
SECURITY DEFINER wrappers (`admin_*`) checks that the caller is an active admin, applies the "never another admin" and
self-protection rules, then calls the matching `adm_*`. The Edge Function resolves a token to `{ memberId, isAdmin }`
and registers the 12 `admin_` tools only for admins.

**Tech Stack:** as the existing project: Postgres 17 migrations + pgTAP, Deno, `npm:postgres@3.4.5`,
`npm:@modelcontextprotocol/server@2.4.0`, `npm:zod@4.6.7`.

**Spec:** [docs/superpowers/specs/2026-11-07-mcp-admin-design.md](../specs/2026-11-07-mcp-admin-design.md)

## Global Constraints

- **All schema changes are a NEW migration:** `supabase/migrations/20261107150000_admin.sql`. Existing migrations are
  applied to the hosted project and must not change. `supabase db reset` from empty must build everything.
- Every function: `security definer`, `set search_path = ''`, fully qualified names. `revoke execute … from public`,
  then grant exactly as each task says.
- `adm_*` functions are executable by `postgres` only. `admin_*` functions are executable by `agent_memory_member`.
- **A bot can never be an admin.** Enforce with a CHECK constraint `kind = 'human' or not is_admin`.
- **Admin tools never act on another admin.** Every `admin_*` that names a member other than the caller, or acts on a
  token or grant belonging to one, raises `Member '<name>' is an admin; manage admins from the shell`.
- **`admin_log` never stores a token value or hash**, and `agent_memory_member` has no privilege on it.
- No token expiry is offered through the MCP.
- Error messages raised by `adm_*` and `admin_*` are user-safe, and the TS layer returns them verbatim. Exact texts are
  in Task 1's Interfaces. A non-admin calling an `admin_*` function gets `42501 Admin only`.
- Tool results use the existing shape `{ content: [{ type: 'text', text: JSON.stringify(data, null, 2) }] }`;
  failures add `isError: true`.

## Review Focus

1. **Names are matched exactly.** `Rik` vs `rik`, or a trailing space, must give `Member 'Rik' not found`, never act on a
   different member. Test: Task 2, `member names match exactly`.
2. **Revoking another admin's token by its id.** Token ids are visible to admins only for themselves and non-admins.
   Even a guessed id belonging to another admin must be refused. Test: Task 2,
   `revoke_token refuses another admin's token`.
3. **A deactivated member's existing token stops working at once.** Expected: 401 on the next request. Tests: Task 1
   `deactivated tokens stop resolving` and Task 5 e2e.
4. **A scope holding only soft-deleted memories.** Expected: delete refused, with the count. Test: Task 1,
   `delete_scope counts soft-deleted memories`.
5. **Issuing a token for a deactivated or unknown member.** Expected: an error, and no token row created. Test:
   Task 2, `issue_token refuses deactivated and unknown members`.

### Task 1: Schema, token resolution, and the `adm_*` core functions

**Files:**
- Create: `supabase/migrations/20261107150000_admin.sql`, `supabase/tests/database/06_admin_core.test.sql`

**Interfaces:**
- Produces (schema):
  - `members.is_admin boolean not null default false`;
  - `members.deactivated_at timestamptz`;
  - constraint `members_bot_not_admin check (kind = 'human' or not is_admin)`;
  - `agent_memory.admin_log (id bigint generated always as identity primary key, at timestamptz not null default now(), actor_member_id uuid null, actor_label text not null, action text not null, target text not null, details jsonb not null default '{}')`.
- Produces (postgres-only functions; every one appends one `admin_log` row on success):
  - `resolve_token(p_hash text) returns uuid`, redefined with `create or replace`: as before, but also requires the member's `deactivated_at is null`.
  - `resolve_member(p_hash text) returns table (member_id uuid, is_admin boolean)`: the same rules plus the flag. Empty when unresolved.
  - `adm_create_scope(p_name text, p_description text, p_actor uuid, p_label text) returns uuid`
  - `adm_delete_scope(p_name text, p_actor uuid, p_label text) returns void`
  - `adm_create_member(p_name text, p_kind text, p_email text, p_actor uuid, p_label text) returns uuid`: links `auth_user_id` by case-insensitive email, as `createMember` does today.
  - `adm_deactivate_member(p_name text, p_actor uuid, p_label text) returns void`: revokes all live tokens, deletes all grants, sets `deactivated_at`.
  - `adm_reactivate_member(p_name text, p_actor uuid, p_label text) returns void`: clears `deactivated_at`; no grants or tokens restored.
  - `adm_set_admin(p_name text, p_on boolean, p_actor uuid, p_label text) returns void`
  - `adm_grant(p_member text, p_scope text, p_access text, p_actor uuid, p_label text) returns void`: upsert.
  - `adm_revoke(p_member text, p_scope text, p_actor uuid, p_label text) returns boolean`: false if there was no grant.
  - `adm_issue_token(p_member text, p_name text, p_hash text, p_expires timestamptz, p_actor uuid, p_label text) returns uuid`: the caller hashes the token; only the hash is stored, and the log gets the token id and name.
  - `adm_revoke_token(p_id uuid, p_actor uuid, p_label text) returns void`
- Exact error texts (`raise exception '…'`, default SQLSTATE P0001):
  - `Scope '%' not found`, `Member '%' not found`, `Token % not found`
  - `Scope '%' already exists`, `Member '%' already exists`
  - `Scope names are lowercase letters, digits and hyphens, starting with a letter or digit (max 63)`
  - `Scope '%' still holds % memories; move, delete or erase them first`: counts live AND soft-deleted memories.
  - `Member '%' is deactivated`: for grant and issue_token.
  - `A bot can't be an admin`
  - `Can't remove the last active admin`
  - `Access must be read or write`

### Task 2: Admin-only wrappers for members

**Files:**
- Modify: `supabase/migrations/20261107150000_admin.sql` (append; still unpushed)

**Interfaces:**
- Consumes: Task 1's `adm_*`.
- Produces (SECURITY DEFINER, executable by `agent_memory_member` only):
  - Private helper `agent_memory.require_admin() returns uuid`: returns `current_member_id()` when that member is active
    and `is_admin`, else raises `Admin only` with SQLSTATE `42501`.
  - Every wrapper starts with `require_admin()` and passes `p_actor = caller`, `p_label = <caller display name>`.
  - `admin_create_scope(p_name text, p_description text) returns uuid`
  - `admin_delete_scope(p_name text) returns void`
  - `admin_create_member(p_name text, p_kind text, p_email text) returns uuid`
  - `admin_deactivate_member(p_name text) returns void`: refuses the caller (`You can't deactivate yourself`) and other admins.
  - `admin_grant(p_member text, p_scope text, p_access text) returns void`: refuses other admins; the caller may grant themselves.
  - `admin_revoke(p_member text, p_scope text) returns boolean`: same rule.
  - `admin_issue_token(p_member text, p_name text, p_hash text) returns uuid`: no expiry; refuses other admins; the caller may issue their own.
  - `admin_revoke_token(p_id uuid) returns void`: refuses if the token's owner is another admin. Refuses the caller's own last live token (`You can't revoke your last live token`).
  - Listing (return tables; no hashes anywhere):
    - `admin_list_scopes() returns table (name text, description text, memories int, deleted int, readers int, writers int)`
    - `admin_list_members() returns table (name text, kind text, email text, is_admin boolean, deactivated boolean, live_tokens int)`
    - `admin_list_grants(p_scope text, p_member text) returns table (scope text, member text, access text, granted_at timestamptz, granted_by text)`: nulls mean unfiltered.
    - `admin_list_tokens(p_member text) returns table (id uuid, name text, created_at timestamptz, last_used_at timestamptz, revoked_at timestamptz)`: refuses another admin's tokens.
  - There is no wrapper for `adm_set_admin` or `adm_reactivate_member`.

### Task 4: Admin store and the 12 admin MCP tools

**Files:**
- Create: `supabase/functions/_shared/admin-store.ts`, `supabase/functions/_shared/admin-tools.ts`
- Test: `tests/integration/admin-store.test.ts`, `tests/unit/admin-tools.test.ts`

**Interfaces:**
- Consumes: Task 2's `admin_*` via `withMember` (db.ts); `generateToken`/`hashToken` (tokens.ts).
- Produces:
  - `class PgAdminStore { constructor(sql: Sql, memberId: string) }` with methods: `listScopes()`,
    `createScope(name, description?)`, `deleteScope(name)`, `listMembers()`,
    `createMember(name, kind: 'human' | 'bot', email?)`, `deactivateMember(name)`,
    `listGrants(f?: { scope?: string; member?: string })`, `grant(member, scope, access)`, `revoke(member, scope)`,
    `issueToken(member, name): Promise<{ id: string; token: string }>`, `listTokens(member)`, `revokeToken(id)`.
  - Error mapping:
    - P0001 → `StoreError(message)` with the message unchanged;
    - 42501 → `StoreError('Admin only')`;
    - 22P02 (bad uuid) → `StoreError('Token <id> not found')`;
    - anything else → logged with code and message, then `StoreError('Database error')`.
  - `registerAdminTools(server: McpServer, admin: PgAdminStore): void` registers exactly these 12 tools:
    `admin_list_scopes`, `admin_create_scope`, `admin_delete_scope`, `admin_list_members`, `admin_create_member`,
    `admin_deactivate_member`, `admin_list_grants`, `admin_grant`, `admin_revoke`, `admin_issue_token`,
    `admin_list_tokens`, `admin_revoke_token`.
    - zod inputs: `name`/`member`/`scope` are strings; `kind` is `enum(['human','bot'])` defaulting to `human`;
      `access` is `enum(['read','write'])`; `email`, `description` and the list filters are optional; `id` is a string.
    - Each description starts with `Admin:`.
    - `admin_issue_token`'s description and result both say the token is shown once and is not stored. The result is
      `{ member, name, id, token, note: 'Shown once - give it to the member privately; it is not stored and cannot be shown again.' }`.
    - `admin_deactivate_member`'s description says it revokes all tokens and grants, and is undone only from the shell.
